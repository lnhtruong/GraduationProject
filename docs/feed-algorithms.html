Feed Algorithms
Recommendation & Trending

Tài liệu chi tiết thuật toán gợi ý video cá nhân hoá và bảng xếp hạng trending — từ cron job, Redis, công thức tính điểm đến toàn bộ pipeline.

Tổng quan hệ thống

Hệ thống feed gồm hai luồng song song, mỗi luồng có cron job riêng và Redis cache riêng:

LuồngMục tiêuCronRedis TTL
Personalized Recommendation Gợi ý video phù hợp với từng user dựa trên lịch sử hành vi EVERY_MINUTE 600s
Trending Feed Bảng xếp hạng công khai — video hot nhất trong 1 giờ qua EVERY_5_MINUTES 300s

Cả hai job đều được bảo vệ bởi hai lớp khóa: cờ isPrecomputing / isRefreshingTrending tại process level (chặn overlap trong cùng một replica) và Redis distributed lock (chặn overlap khi deploy nhiều replica).

Trending Feed — Cron Job EVERY_5_MINUTES

File feed-recommendation.worker.ts, method handleTrendingRefresh(), được đăng ký với NestJS Scheduler qua decorator @Cron(CronExpression.EVERY_5_MINUTES). 

// feed-recommendation.worker.ts
private isRefreshingTrending = false;  // cờ process-level

@Cron(CronExpression.EVERY_5_MINUTES)
async handleTrendingRefresh(): Promise<void> {
  if (this.isRefreshingTrending) {
    return;  // bỏ tick này nếu job trước chưa xong
  }
  this.isRefreshingTrending = true;
  try {
    const result = await this.feedService.refreshTrendingCache();
    // log: items=N duration=Xms
  } finally {
    this.isRefreshingTrending = false;
  }
}

Lớp bảo vệ thứ 2: Bên trong refreshTrendingCache(), service gọi redisService.acquireLock("feed:trending:refresh:lock", 30) trước khi tính toán. Nếu lock đang bị giữ (replica khác đang chạy), method trả về { skipped: true } ngay lập tức.

Tính điểm Trending — computeTrendingFeedIds()

Hàm thực hiện 4 bước:

1
Lấy danh sách feed ứng viên

Query highlight_feed với status = 'active' JOIN courses với status = 'PUBLISH'. Chỉ feed thuộc khoá học đang mở mới được xét.

2
Xác định cửa sổ thời gian

startDate = now − TRENDING_WINDOW_MS → mặc định là 1 giờ (3 600 000 ms). Chỉ các tương tác sau thời điểm này được tính.

3
Aggregate tương tác (3 query song song)

feedInteractionModel → SUM likes, saves, shares theo highlight_id
feedViewModel → COUNT views theo highlight_id
feedCommentModel → COUNT comments theo highlight_id
Ba query chạy đồng thời qua Promise.all().

4
Tính điểm, sort, trả danh sách ID

Áp công thức trending score cho mỗi feed, sort DESC, tiebreaker là feedId DESC (feed mới hơn thắng khi bằng điểm).

Công thức điểm Trending

trendingScore = likes × 3 + saves × 4 + shares × 5 + comments × 2 + views × 0.5
Tất cả giá trị là số tương tác trong 1 giờ gần nhất
Feed không có tương tác nào → score = 0 → đứng cuối (hoặc không xuất hiện)

Lý do chọn trọng số

Tín hiệuTrọng sốLý do
share×5Share tốn effort cao nhất — người dùng thực sự thấy có giá trị mới share
save×4Save = "muốn xem lại" — intent rõ ràng hơn like
like×3Positive signal nhưng cost thấp, dễ click
comment×2Engagement đủ mạnh nhưng volume thấp hơn like
view×0.5View đông nhưng passive — không bằng chứng chất lượng, chỉ boost nhẹ
📝

Trending stats API (GET /feed/stats/trending) dùng công thức mở rộng hơn: thêm + completionRate × 2 để admin thấy thêm chiều "watch-through quality". Công thức trên (không có completion rate) là công thức public trending dùng cho trang người dùng.

Redis Cache cho Trending

// refreshTrendingCache() — feed.service.ts:1280
async refreshTrendingCache() {
  const lockKey = 'feed:trending:refresh:lock';
  const acquired = await this.redisService.acquireLock(lockKey, 30); // TTL 30s
  if (!acquired) return { skipped: true };

  try {
    const ids = await this.computeTrendingFeedIds();
    await this.redisService.set(
      'feed:trending:1h',
      JSON.stringify(ids),
      300,  // TTL 300 giây = 5 phút
    );
    return { count: ids.length };
  } finally {
    await this.redisService.releaseLock(lockKey);
  }
}
KeyTypeTTLNội dung
feed:trending:1h String 300s JSON array các feed_id sorted by trendingScore DESC, tối đa 50 items
feed:trending:refresh:lock String 30s Distributed lock — value = "1", tự hết hạn sau 30s

Recommendation — Cron Job EVERY_MINUTE

Method handlePrecompute() chạy mỗi 60 giây, gọi vào feedService.precomputeRecommendedForActiveUsers({ concurrency: 8, maxBatch: 500 }).

Tại sao cần precompute?

Khi user mở app và gọi GET /feed?mode=recommended, họ kỳ vọng response <100ms. Tính toán ranking real-time cho 100 video candidates với đầy đủ DB query không thể đạt được latency đó. Precompute giải quyết vấn đề này: cron job tính trước, lưu kết quả vào Redis, request của user chỉ việc đọc cache.

Luồng precomputeRecommendedForActiveUsers()

// feed.service.ts:1204
async precomputeRecommendedForActiveUsers(options?) {
  // 1. Acquire distributed lock (TTL 60s)
  const acquired = await this.redisService.acquireLock('feed:rec:precompute:lock', 60);
  if (!acquired) return { processed: 0, skipped: 0 };

  try {
    // 2. Lấy user queue từ Redis set 'feed:rec:interacted-users'
    const members = await this.redisService.sMembers('feed:rec:interacted-users');
    const batch = userIds.slice(0, maxBatch); // lấy tối đa 500 user/lần

    // 3. Process với bounded concurrency (8 user song song)
    const workers = Array.from({ length: 8 }, async () => {
      while (queue.length > 0) {
        const userId = queue.shift();
        const sessionId = existingSession ?? generateNew(); // tái dùng session
        const { rankedFeeds } = await this.computeRankedCandidates(userId);
        await this.setCachedRecommendList(userId, sessionId, rankedIds);
        await this.setLatestRecommendSessionId(userId, sessionId);
      }
    });
    await Promise.all(workers);

    // 4. Xóa processed users khỏi queue
    await this.redisService.sRem('feed:rec:interacted-users', batch.map(String));
  } finally {
    await this.redisService.releaseLock('feed:rec:precompute:lock');
  }
}

Bước 1 — Xây dựng User Profile

User profile là bộ affinity scores lưu trong Redis, dùng để đo mức độ yêu thích của user với từng khoá học và hashtag.

Cold Start (profile chưa có trong cache)

Đọc 200 view gần nhất từ DB

Query feed_views JOIN highlight_feed, ORDER BY id DESC, LIMIT 200.

Tính behavior weight cho mỗi view

weight = (completed ? 2 : 1) + min(watchDuration / 30, 2)
Ví dụ: xem 60s không xong = (1 + 2) = 3 điểm. Xem hết 10s = (2 + 0.33) ≈ 2.33 điểm.

Cộng dồn vào Map<courseId, number> và Map<hashtag, number>

Mỗi video được xem thêm weight vào courseAffinity[course_id] và từng tag trong hashtagAffinity[tag].

Lưu profile vào Redis 24h

Key feed:rec:profile:{userId}, TTL 86400s. Serialize Maps thành JSON plain object.

Warm Path (profile đã có trong cache)

Load từ Redis. Chỉ cần đọc feed_views để build viewedCount (dùng cho repeat-view penalty) — không cần rebuild affinity từ đầu.

Online Update (khi user tương tác)

Mỗi lần user like, save, hoặc view video, hàm updateProfileAffinity() được gọi ngay lập tức để cập nhật cache. Không cần đợi cron.

Hành độngBehavior Weight
View (không hoàn thành, 30s)(1) + min(30/30, 2) = 2.0
View (hoàn thành, 15s)(2) + min(15/30, 2) = 2.5
View (hoàn thành, 60s+)(2) + min(60/30, 2) = 4.0 (max)

💡

Cooldown window 6h: Redis sorted set feed:rec:seen:{userId} lưu (feedId, timestamp). Khi query, lọc những item có timestamp >= now - 6h. Sau 6h, item tự động ra khỏi "seen" và có thể xuất hiện lại.

Bước 3 — Thu thập Signals

Sau khi có candidate pool, service chạy 2 query song song để lấy dữ liệu cho scoring:

  • getStatsAndInteractions(feedIds, userId) — lấy likes, saves, views (mọi thời gian) + trạng thái liked/saved của user hiện tại
  • getRankingSignals(feedIds, 168h) — aggregate tương tác trong cửa sổ GLOBAL_ENGAGEMENT_WINDOW_HOURS = 7 ngày: likes, saves, shares, views, completedViews, avgWatchDuration

Bước 4 — Công thức điểm Recommendation

recommendationScore = W_GLOBAL × globalScore + W_PERSONAL × personalScore + W_FRESHNESS × freshnessScore + 0.3 × viewBoost − repeatViewPenalty
W_GLOBAL = 1.0  |  W_PERSONAL = 1.5  |  W_FRESHNESS = 1.2

Chi tiết từng thành phần

Global Score ×1.0

Độ phổ biến toàn cục trong 7 ngày qua:

positives = likes + saves×1.5
          + shares×2 + comments×1.2
engagement = (positives + 1)/(views + 50)
    // Wilson/Laplace smoothing
completionRate = completedViews / views
popularity = log₁₀(1 + views + likes×2
    + saves×3 + shares×4)
globalScore = engagement×5
    + completionRate×3 + popularity
Personal Score ×1.5

Mức độ khớp với sở thích user:

courseScore = courseAffinity[course_id]
    / maxCourseAffinity  // [0..1]

tagScore = avg(hashtagAffinity[tag])
    / maxHashtagAffinity  // [0..1]

personalScore = courseScore×0.7
    + tagScore×0.3
Freshness ×1.2

Decay theo thời gian (half-life 36h):

ageHours = (now - created_at) / 3600000
freshnessScore = 0.5 ^ (ageHours / 36)

// Ví dụ:
// mới tạo → 1.0
// 36h    → 0.5
// 72h    → 0.25
// 1 tuần → ~0.03
View Boost ×0.3

Boost nhẹ cho item đã có traction:

viewBoost = log₁₀(1 + views)
    / log₁₀(1 + maxViews)
// Normalised về [0..1]
// Không để viral item áp đảo mãi
Repeat View Penalty −

Trừ điểm nếu user đã xem nhiều lần:

penalty = min(
    viewCount × 0.8,
    3.0  // cap tối đa
)
// 1 lần: −0.8
// 2 lần: −1.6
// ≥4 lần: −3.0 (capped)
Exploration Score phụ trợ

Dùng để chọn item chèn vào exploration slots:

explorationScore = fresh × 2
    − personalScore
// Item mới + chưa trong sở thích
// user → candidate tốt để khám phá

Ví dụ tính điểm cụ thể

Video A — trending, nhưng user đã xem 2 lần, ngoài sở thích
globalScoreengagement=0.4 → 0.4×5=2.0; completionRate=0.6 → 1.8; popularity=2.1 → 5.9
personalScorecourseScore=0.1, tagScore=0.05 → 0.1×0.7+0.05×0.3 = 0.085
freshnessScore24h tuổi → 0.5^(24/36) = 0.63
viewBoost1000 views, maxViews=5000 → log(1001)/log(5001) = 0.75
penalty2 lần xem → min(1.6, 3) = −1.6
Total1.0×5.9 + 1.5×0.085 + 1.2×0.63 + 0.3×0.75 − 1.6 = 5.9 + 0.13 + 0.76 + 0.23 − 1.6 = 5.42
Video B — mới đăng, đúng sở thích user, ít người xem
globalScoreengagement=0.1 → 0.5; completionRate=0.8 → 2.4; popularity=1.0 → 3.9
personalScorecourseScore=0.9, tagScore=0.8 → 0.9×0.7+0.8×0.3 = 0.87
freshnessScore2h tuổi → 0.5^(2/36) = 0.96
viewBoost10 views → nhỏ → 0.2
penaltychưa xem → 0
Total1.0×3.9 + 1.5×0.87 + 1.2×0.96 + 0.3×0.2 − 0 = 3.9 + 1.31 + 1.15 + 0.06 = 6.42

Video B thắng dù ít popular hơn — đây là điểm mấu chốt của personalization: W_PERSONAL = 1.5 đủ mạnh để đẩy nội dung phù hợp lên trên dù chưa viral.

Bước 5a — Exploration Injection (epsilon-greedy)

Sau khi sort, list kết quả có thể bị "filter bubble" — toàn video cùng loại user đã thích. Hàm injectExploration() phá vỡ điều này: 

const everyN = Math.round(1 / EXPLORATION_RATIO); // ≈ 7
// Tách top 50% và bottom 50%
const topCutoff = Math.ceil(ranked.length / 2);
const tail = ranked.slice(topCutoff)
  .sort((a, b) => b.explorationScore - a.explorationScore);

// Cứ mỗi 7 slot trong top, chèn 1 item từ tail
for (let i = 0; i < result.length; i++) {
  finalList.push(result[i]);
  if ((i + 1) % everyN === 0 && tailCursor < tail.length) {
    finalList.push(tail[tailCursor++]);  // chèn exploration item
  }
}
Ví dụ với 14 items:

Top 7: [A, B, C, D, E, F, G] + Bottom 7: [H, I, J, K, L, M, N] (sort theo explorationScore)
Kết quả: [A, B, C, D, E, F, G→H, ...] — H là item mới nhất chưa trong sở thích user.

→

Interaction Flow

Mỗi hành động của user kích hoạt một chuỗi cập nhật:

Insert feed_views record

{ user_id, highlight_id, watch_duration, completed }

Like: weight=1.2 | Save: weight=2.0

invalidateRecommendCache + markUserInteracted

Tương tự view flow bên trên.

Session Management & Cursor Pagination

Recommendation dùng session-based pagination thay vì offset, để đảm bảo thứ tự feed ổn định khi user scroll (không bị duplicate hoặc miss khi list thay đổi).

Cách hoạt động:
  1. Lần đầu gọi: server tạo/lấy sessionId, tính ranked list, cache cả list vào Redis 600s
  2. Response trả về session_id và next_cursor (= feed_id của item cuối trong page)
  3. Request tiếp theo: gửi kèm session_id + cursor, server đọc cùng cached list, skip đến sau cursor
  4. User tương tác → cache bị invalidate → lần gọi tiếp sẽ tạo session mới, tính lại
  5. Session hết hạn (600s) → tương tự tạo mới
// getRecommendedFeed() — feed.service.ts:1077
// 1. Kiểm tra session và cached list
let cachedList = await this.getCachedRecommendList(userId, sessionId);

if (cachedList && cachedList.length > 0) {
  // Fast path: chỉ page từ cache
  const pageIds = this.pageFeedIds(cachedList, cursor, limit);
  return { data, next_cursor, session_id };
}

// Slow path: tính lại từ đầu
const { rankedFeeds } = await this.computeRankedCandidates(userId);
await this.setCachedRecommendList(userId, sessionId, rankedIds); // cache 600s
await this.setLatestRecommendSessionId(userId, sessionId);     // cache 600s

A/B Testing & Điều chỉnh

Cách điều chỉnh an toàn:
  • Sửa các hằng số trong FeedService → deploy → observe metrics
  • Tăng W_PERSONAL → feed cá nhân hoá hơn, ít khám phá mới
  • Tăng EXPLORATION_RATIO → nhiều video ngoài sở thích hơn (phá filter bubble)
  • Giảm FRESHNESS_HALF_LIFE_HOURS → ưu tiên video rất mới hơn
  • Tăng TRENDING_WINDOW_MS → trending phản ánh xu hướng dài hơn (ít sensitive hơn)
  • Giảm SEEN_COOLDOWN_SECONDS → video xuất hiện lại sớm hơn khi user ít nội dung mới
