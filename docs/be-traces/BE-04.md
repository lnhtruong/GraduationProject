## Behaviour

- A reply (parentId != null) by user X to post owned by user Y -> insert a row into `notifications` for Y with:
  - event_type = `discussion.reply.created`
  - title = "Bạn có một câu trả lời mới"
  - message = `"<replyName> đã trả lời câu hỏi của bạn trong bài <lessonTitle>"`
  - payload.redirectUrl = `/courses/<courseId>/lessons/<lessonId>#discussion-<rootId>`
  - source_type = `discussion_post`, source_id = reply id
- Reply to self (X = Y) -> no notification.
- If the parent is itself a reply, the notifier walks up to the root (`parent.parentId ?? parent.id`) and notifies the root author.
- WebSocket emit (`notification:new`) is intentionally not wired here — the existing notification table is what the frontend polls / SSEs through media_service; coupling course_service to the WS bus is out of scope for BE-04.
