## Design notes
- Route ordering: /users/:id (existing) shadows /users/following. Fixed by registering FollowsModule BEFORE UsersModule in AppModule imports. Same ordering in access-policy.ts.
- No new Course model in user_service. courseCount is fetched via raw sequelize.query against `courses`.
- isFollowing semantics: undefined if request has no x-user-id header (public mode); false if requester is the instructor themselves; true/false otherwise.
- Idempotent follow: double-protected (findOrCreate + unique-key catch).
