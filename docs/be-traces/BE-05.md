## Schema
| Column | Type | Notes |
|---|---|---|
| id | INT UNSIGNED PK AI | |
| user_id | INT NOT NULL | FK -> users.id ON DELETE CASCADE |
| course_id | INT NOT NULL | FK -> courses.id ON DELETE CASCADE |
| added_at | DATETIME | default CURRENT_TIMESTAMP |

Unique key: (user_id, course_id) — guarantees idempotency.

## Endpoints (URLs through gateway)

| Method | Path | Behaviour |
|---|---|---|
| GET | /api/course/wishlist | paginated list with CourseCard fields (avg rating, review count, enroll count, instructor) |
| POST | /api/course/wishlist | body `{ courseId }`; idempotent via findOrCreate; rejects courses not in status `publish` (400) |
| DELETE | /api/course/wishlist/:courseId | 204 if existed, 404 otherwise |
| GET | /api/course/wishlist/check/:courseId | `{ inWishlist: boolean }` for tim-icon UI |

## Design notes
- Instructor info is batch-fetched after the main query rather than via Sequelize association, because Course does not currently expose an `instructor` BelongsTo. Avoids modifying a shared model.
- avgRating / reviewCount / enrollCount are computed via correlated subqueries in the Course include (subQuery: false to keep LIMIT correct).
- findOrCreate makes POST idempotent even under concurrent requests — the unique key prevents duplicate rows at the storage layer too.
