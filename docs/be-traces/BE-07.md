## Behaviour
- POST /api/instructors/:id/follow (fresh insert only) -> one notification for the instructor (event_type=instructor.follow.new).
- POST /api/course/courses/:id/publish (approved -> publish) -> batch-create one notification per follower (event_type=course.publish.new_from_instructor). Payload carries courseId, courseName, instructorId, instructorName, redirectUrl.
- Both wrapped in try/catch — failure logs warning, never breaks user action.
- Zero followers -> publish succeeds, zero notifications, no error.

## Performance
- Batch chunk size = 200, matches spec's "không timeout dưới 3s for 500 followers" (500 followers -> 3 chunks).
- Follower list query selects only `followerId` to keep payload minimal.
