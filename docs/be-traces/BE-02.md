## Endpoints (URLs through gateway)

| Method | Path | Access | Notes |
|---|---|---|---|
| GET | /api/course/lessons/:lessonId/discussions | authenticated | enrolment guard at service |
| POST | /api/course/lessons/:lessonId/discussions | authenticated | enrolment guard; supports parentId for replies |
| PATCH | /api/course/discussions/:postId | authenticated | author-only |
| DELETE | /api/course/discussions/:postId | authenticated | author OR course instructor OR admin (204) |
| GET | /api/course/courses/:courseId/discussions | LECTURER/ADMIN | instructor isolation |

## Service-level guards

- Read/Post (lesson-scoped): must be enrolled in the lesson's course, OR be the course instructor, OR be admin.
- Edit (PATCH): author only — 403 otherwise.
- Delete: author, course instructor (role 3), or admin — 403 otherwise.
- Course-level list: course instructor or admin only.

## Reply / nesting logic

Two-level nesting only (root + replies). If parentId points at a reply, the new post is re-anchored to the root (`parent.parentId ?? parent.id`). Verified with curl: posting `parentId=<reply-id>` returned `parentId=<root-id>`.

## List response shape

```
{ data: [ { id, lessonId, parentId, content, isBestAnswer, upvotes,
           createdAt, updatedAt, author: {id,name,avatarUrl}, replies: [...] } ],
  total, page, limit }
```

Course-level list adds lessonTitle and replyCount per item and supports `?lessonId=&status=answered|unanswered` (status = has-replies test via a correlated subquery).

## Design notes

- No dedicated NestJS guard class — auth enforced at the service layer using x-user-id/x-user-role headers (same pattern as feedbacks module). The gateway already does role gating in access-policy.ts; enrolment is a per-course check the gateway cannot do.
- subQuery: false on findAndCountAll for the course-level list to keep the correlated subquery (status filter) valid under the outer LIMIT/OFFSET.
- replyCount is computed via a single grouped query against parent_id IN (rootIds), avoiding N+1.
- 2-level nesting re-anchor is the cleanest UX-side guarantee — front-end never sees a 3-deep tree even if a client sends a stale parent.
