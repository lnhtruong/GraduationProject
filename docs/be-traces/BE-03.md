# BE-03 — Upvote toggle + Best Answer

**Branch:** `feat/TT-BE-03` (branched off `feat/TT-BE-02`)
**Scope:** M1 · Discussion Forum — interactions on top of BE-02.

## Endpoints added

| Method | Path | Access | Behaviour |
|---|---|---|---|
| POST | /api/course/discussions/:postId/upvote | authenticated | toggle insert/delete in discussion_upvotes; returns `{ upvotes, voted }` |
| PATCH | /api/course/discussions/:postId/best-answer | LECTURER/ADMIN (gateway) + course-owner check at service | toggle; only one best-answer per root question; only on replies |

ACL entries for these two endpoints were added in BE-02's commit so the gateway already routes them.

## Files modified
- `backend_services/course_service/src/discussions/discussions.service.ts`
  - `toggleUpvote(postId, userId)` — transaction with `SELECT ... FOR UPDATE` on the post + best-effort INSERT into `discussion_upvotes`; `UniqueConstraintError` is treated as a lost race (returns current count, `voted: true`).
  - `toggleBestAnswer(postId, userId, role)` — verifies caller is instructor of the lesson's course or admin; rejects when the target post is a root question (`parentId === null`); ensures only one best-answer reply per root by un-setting siblings inside the same transaction.
- `backend_services/course_service/src/discussions/discussions.controller.ts`
  - `@Post('discussions/:postId/upvote')`
  - `@Patch('discussions/:postId/best-answer')`

## Concurrency & data integrity

- Upvote uses Transaction.LOCK.UPDATE on the post row — atomic counter increment with the insert/delete on discussion_upvotes.
- UNIQUE (post_id, user_id) on discussion_upvotes is the second line of defence — race-collision is swallowed in catch and returns deterministic "already voted".
- Counter never drops below 0 (Math.max(0, post.upvotes - 1)).
